Vessel 0.3.5 adds unrealized P&L to Activity, in place of the Play column.

No migrations and no configuration changes: this is a drop-in patch release.

## Highlights

- **Unrealized P&L in Activity.** Open operations show what the remaining
  position is worth right now, before fees and funding, in both Journal and Paper
  playground. Hyperliquid, RISEx and Paper (which uses Hyperliquid prices) mark
  the remainder at the venue's current mark price. Lighter, which publishes no
  market context, shows the venue-reported figure from your latest refresh, but
  only if that refresh is newer than the last execution and holds exactly the
  remaining position. Closed operations show "—", and an open operation that
  cannot be priced says "Unavailable" rather than showing zero. The tooltip gives
  the exact value, the mark price or refresh and when it was read.
- **Observations, not results.** These values are read for the shown page only
  and are kept out of the Activity change detector, so a moving price never
  reports changed history. They never enter Review, sizing, Overview or Play
  results, and a mark is never treated as a fill.
- **Play link in the expanded row.** The linked Play's title, or Journal this
  trade for a closed operation that is not on a Play, now sits in the expanded
  row. Journal this trade replaces "Inspect retrospective eligibility" there,
  because both opened the same preview. The compact Overview and account tables
  are unchanged.
- **Steadier tests.** The startup warm-up readiness tests no longer race their
  deadline on a busy machine. Production behaviour is unchanged.

## Upgrading from 0.3.4

1. Stop web, every API and every worker, take your usual backups and keep your
   Compose project, owner GUID and overlays.
2. Replace the deploy files with this release's versions and set
   `VESSEL_VERSION=0.3.5`.
3. Pull matching API and web images and run the explicit `migrate` service as
   usual. It applies nothing new: there are **no new identity or journal
   migrations** from v0.3.4. No application host migrates at startup.
4. Start the services. Upgrade the API and web images together so the new column
   has its data.

Follow the [start sequence](https://github.com/sloppitty/vessel/blob/v0.3.5/deploy/README.md#start-and-connect).
Earlier installations must also follow their intervening upgrade requirements.
Rollback needs the previous deploy files and private configuration with matching
previous images; no data change is involved.

## Known limits

- Unrealized P&L is an estimate at a mark price, before fees and funding. It is
  not a fill, a close price or a result, and it is not stored.
- If a venue's price read fails or the market is not in its catalogue, the value
  shows "Unavailable" until the next successful read. A Lighter value is the
  last refresh's, so it can be stale until you refresh the account.
- Wallet acceptance §10 remains **not signed off**: the real-wallet/non-mainnet
  EOA check is owner-pending. Keep registration `Closed` until it is recorded in
  [the identity state](https://github.com/sloppitty/vessel/blob/v0.3.5/docs/architecture/multi-user-state.md).
- This release does not change execution scoring, sizing, Review or funding
  rules.
