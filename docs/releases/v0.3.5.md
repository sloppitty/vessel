Vessel 0.3.5 adds phone sign-in through desktop pairing and unrealized P&L in
Activity.

This release requires one identity migration. There are no new journal
migrations or required configuration settings.

## Highlights

- **Connect a phone without a wallet on it.** On a signed-in computer, open
  Settings → Sessions → Connect a phone and approve one wallet signature.
  Scan the single-use QR with the phone's camera app or Vessel's "Scan a code
  from your desktop". You can type a code instead if scanning fails. The phone
  shows a six-digit code that you must type on the computer to approve it.
  Each pairing step has a two-minute deadline, and a second device claiming
  the same pairing cancels it.
- **A separate, revocable session.** The phone gets full access to the same
  journal through its own session, labelled "Paired" in Settings → Sessions.
  The QR contains no private key, venue credential or existing session token.
  "Keep me signed in" is checked by default on the phone. Its default idle
  limit, and that of remembered wallet sign-ins, is now 10 days instead of 14.
  The 30-day absolute limit is unchanged. An explicitly configured
  `Vessel:Identity:Session:RememberIdleDays` keeps its value.
- **Unrealized P&L in Activity.** Open operations show what the remaining
  position is worth right now, before fees and funding, in both Journal and Paper
  playground. Hyperliquid, RISEx and Paper (which uses Hyperliquid prices) mark
  the remainder at the venue's current mark price. Lighter, which publishes no
  market context, shows the venue-reported figure from your latest refresh, but
  only if that refresh is newer than the last execution and holds exactly the
  remaining position. Closed operations show "—", and an open operation that
  cannot be priced says "Unavailable" rather than showing zero. The tooltip gives
  the exact value, the mark price or refresh and when it was read.
- **Observations, not results.** These values are read for the shown page only
  and are kept out of the Activity change detector, so a moving price never
  reports changed history. They never enter Review, sizing, Overview or Play
  results, and a mark is never treated as a fill.
- **Play link in the expanded row.** The linked Play's title, or Journal this
  trade for a closed operation that is not on a Play, now sits in the expanded
  row. Journal this trade replaces "Inspect retrospective eligibility" there,
  because both opened the same preview. The compact Overview and account tables
  are unchanged.
- **Steadier tests.** The startup warm-up readiness tests no longer race their
  deadline on a busy machine. Production behaviour is unchanged.

## Upgrading from 0.3.4

1. Stop web, every API and every worker, including `worker-notifications` and
   any optional Paper worker. Back up both identity and journal schemas,
   evidence and the credential key ring. Keep your Compose project, owner GUID
   and overlays.
2. Replace the deploy files with this release's versions and set
   `VESSEL_VERSION=0.3.5`.
3. Pull matching API and web images and run the explicit `migrate` service.
   It applies identity migration `20261027213124_DevicePairing`, which adds
   pending pairings and session-source tracking. There are no new journal
   migrations from v0.3.4. No application host migrates at startup.
4. Start the services. Upgrade API and web together for the pairing endpoints
   and Activity fields. Pairing requires an HTTPS origin reachable from both
   devices. A desktop loopback address cannot connect a phone. The web image
   now allows the camera on the same origin through
   `Permissions-Policy: camera=(self), microphone=(), geolocation=()`.

Follow the [start sequence](https://github.com/sloppitty/vessel/blob/v0.3.5/deploy/README.md#start-and-connect).
Earlier installations must also follow their intervening upgrade requirements.
Rollback requires the pre-upgrade backup, previous deploy files and private
configuration with matching previous images. Do not try a rolling downgrade.
Follow the deployment guide's
[restore procedure](https://github.com/sloppitty/vessel/blob/v0.3.5/deploy/README.md#isolated-restore),
including identity reset and event-epoch rotation before restarting hosts.

## Known limits

- Real-phone pairing on an HTTPS origin and the physical camera scanner still
  need an owner check. Automated tests cover the pairing flows and mocked
  scanner, but do not establish physical-device acceptance. See
  [the pairing state](https://github.com/sloppitty/vessel/blob/v0.3.5/docs/architecture/device-pairing-state.md).
- Pairing requires a signed-in computer and a wallet signature there. It is not
  independent account recovery, and it grants full journal access rather than
  restricted phone access.
- Unrealized P&L is an estimate at a mark price, before fees and funding. It is
  not a fill, a close price or a result, and it is not stored.
- If a venue's price read fails or the market is not in its catalogue, the value
  shows "Unavailable" until the next successful read. A Lighter value is the
  last refresh's, so it can be stale until you refresh the account.
- Wallet acceptance §10 remains **not signed off**: the real-wallet/non-mainnet
  EOA check is owner-pending. Keep registration `Closed` until it is recorded in
  [the identity state](https://github.com/sloppitty/vessel/blob/v0.3.5/docs/architecture/multi-user-state.md).
- This release does not change execution scoring, sizing, Review or funding
  rules.
