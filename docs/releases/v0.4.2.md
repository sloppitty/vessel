Vessel 0.4.2 fixes the Play editor's Account field in Brave.

This release has no migrations and no configuration changes.

## Highlights

- **Selected account visible in Brave.** The account picker's trigger used a
  `:has()`-applied container query to hide the venue tag in narrow fields. Brave
  laid that container out 0px tall, so a selected RISEx account showed nothing in
  the Play editor's Account field. The container query is removed; the venue tag
  now shrinks and truncates before the account name does. Other browsers look
  the same.

## Upgrading from 0.4.1

1. Replace the deploy files with this release's versions and set
   `VESSEL_VERSION=0.4.2`.
2. Pull matching API and web images. There are no new identity or journal
   migrations; running the explicit `migrate` service finds nothing to apply.
3. Restart the services. Upgrade API and web together.

Follow the [start sequence](https://github.com/sloppitty/vessel/blob/v0.4.2/deploy/README.md#start-and-connect).
Installations older than 0.4.0 must first follow the
[0.4.0 upgrade](https://github.com/sloppitty/vessel/blob/v0.4.2/docs/releases/v0.4.0.md#upgrading-from-035),
including its thirteen journal migrations and the one-time
`play-search-rebuild --apply`. Rolling back to 0.4.1 needs only the previous
images and deploy files, since no schema changed.
