Vessel 0.3.4 simplifies sign-in to Ethereum wallets only and adds a shared
navigation header with a clearer Journal/Paper playground switch.

**Breaking upgrade:** API token sign-in is removed. Configure HTTPS and bind
the operator's wallet before starting the new images. Existing journal data
stays with the same owner GUID.

## Highlights

- **Wallet-only sign-in.** The token connection screen and Token-mode Settings
  are gone. Every host and offline configuration/migration command rejects a
  configured API token or a mode other than `Wallet`; readiness waits for a
  bound operator wallet. The main Compose file now carries the identity
  settings, with registration `Closed` by default; the separate Wallet overlay
  is removed.
- **Navigation with context.** A sticky header shows shared notices and a
  session-only breadcrumb. Drill-downs keep their location, revisits shorten
  the trail, and saved-Play navigation protects unsaved work. Superseded requests
  cannot replace the current editor.
- **Journal and Paper playground.** The brand subtitle switches modes, with an
  in-app confirmation before discarding unsaved or in-flight Play work. Paper
  uses a paper-boat mark and theme-derived accents, with one header disclosure
  instead of repeated Paper chips. Simulation explanations remain visible;
  financial facts and results stay separate. Reduced motion skips the switch
  animation.
- **Wallet-based local development.** The development runner migrates identity,
  ensures the owner and supports `pnpm dev:identity` for binding a development
  wallet. Workers also start in Development without registering API authorization.

## Upgrading from 0.3.3

1. Stop web, every API and every worker/replica on all hosts, including
   `worker-notifications` and any optional `worker-paper`. Back up both database
   schemas, evidence, credential keys and private configuration. Preserve the
   Compose project, owner GUID and storage/credential/TLS overlays. Do not use
   a rolling upgrade.
2. Replace the deploy files with this release's versions. Remove
   `compose.wallet.yaml` and its entry from `COMPOSE_FILE`: its identity settings
   now live in `compose.yaml`. Set `VESSEL_VERSION=0.3.4`.
3. For an installation that used Token sign-in, remove `Vessel__Auth__Token` and
   `VESSEL_AUTH_MODE` from the private configuration. Set
   `VESSEL_IDENTITY_ORIGIN` to the installation's public HTTPS origin, retain
   the required HTTPS overlay/proxy, and set
   `VESSEL_IDENTITY_REGISTRATION=Closed`. **Keep `Vessel__Auth__OwnerId`
   unchanged**: it owns the journal and binds credential encryption. If it is
   the legacy default GUID, explicitly allow that GUID rather than changing it.
   Check custom overlays and service environments for retired token settings too.
4. With the complete overlay set, run `docker compose config --quiet`, pull
   matching API/web images and run the explicit `migrate` service. There are
   **no new identity or journal migrations** from v0.3.3; the wrapper still
   validates settings, ensures the
   operator and provisions messaging. Token installations must then run
   `identity bind-wallet` for the existing owner GUID and the operator's public
   EOA address before `up`. Never supply a private key or seed phrase.
   Installations already using Wallet sign-in keep their bindings.
5. Start the services and sign in over HTTPS. Verify the existing portfolios,
   accounts and Plays, evidence reads, and worker health. Browser appearance
   and chart preferences move to the operator on first sign-in.

Follow the complete
[token-to-wallet procedure](https://github.com/sloppitty/vessel/blob/v0.3.4/deploy/README.md#moving-from-the-api-token-to-wallet-sign-in)
and [start sequence](https://github.com/sloppitty/vessel/blob/v0.3.4/deploy/README.md#start-and-connect).
Earlier installations must also follow their intervening upgrade requirements,
including the v0.3.0 order-identity restriction. No application host migrates at
startup. Rollback requires the previous deploy files and private configuration
as well as matching previous images; retain the pre-upgrade backup.

## Known limits

- Wallet sign-in supports browser-wallet EOAs, not WalletConnect or
  smart-contract wallets. HTTPS is required outside Development. The signed
  message fixes Chain ID 1 without requesting a network switch; it is not a
  transaction or approval.
- Wallet acceptance §10 is **not signed off**: the real-wallet/non-mainnet EOA
  check remains owner-pending. Keep registration `Closed` until all acceptance
  checks pass and are recorded in
  [the identity state](https://github.com/sloppitty/vessel/blob/v0.3.4/docs/architecture/multi-user-state.md).
  Synthetic checks do not replace that human compatibility check.
- Breadcrumbs are browser-session navigation, not durable browser history.
  Switching trading mode discards unsaved Play work only after confirmation.
- Paper remains opt-in and Hyperliquid-only, with no manual gap/ambiguity
  resolution or simulated-close endpoint. Open/unresolved virtual equity stays
  unknown; simulated touches never confirm actual venue fills.
- Imports remain bounded and funding stays separate without a proven combined
  result basis. This release does not change execution scoring or sizing rules.
