Vessel 0.3.3 brings the trade journal's planning, execution and review closer
together, strengthens stop coverage and sizing, and adds an opt-in paper
playground isolated from real accounts.

## Highlights

- **Close the learning loop.** Complete review, Review again and No review
  needed make completion explicit. Timestamped in-trade Log notes stay separate.
  Recent lessons return to planning through a nonblocking pre-flight checklist.
  Review connects process answers and mistake tags to the exact Plays behind
  each count; shares wait for their own sample of at least ten.
- **Compare plan and execution.** Entry receipts show planned and actual prices
  and quantities. Charts mark fills and open completed trades on their own
  dates. Play-local and scored results carry their own basis labels, with
  estimated initial R and sign differences made visible.
- **Handle difficult records deliberately.** Declare a stuck Open Play
  Unresolved with a reason and execution snapshot, without inventing a result.
  Correct several manual executions atomically with one reason and retained
  history. Activity offers Journal this trade for eligible closed operations.
- **More trustworthy protection and sizing.** Filled entries can have reasoned
  break-even or profitable stops; planning cannot create a break-even stop
  before a fill. Linked levels can be rebound atomically. Monitor incidents and
  stop coverage are visible throughout the workspace. Sizing uses normalized
  available balance, preserves known zero, requires priced stops and follows
  actual exit order with consecutive recovery wins.
- **Review imported positions.** Automatic inclusion uses closed unassigned
  eligible positions while the selection has fewer than five scored Plays
  (threshold configurable in Settings). Manual inclusion is available. A Play
  weighs twice a position in selected return metrics; dollar totals, drawdown,
  streaks and counts remain unweighted. Positions gain no inferred plan or R.
- **Opt-in paper playground.** Separate Hyperliquid paper accounts have immutable
  starting capital (4,000 nominal USD by default). The optional standalone
  worker checks closed minute candles hourly by default, configurable separately.
  Eligible touches simulate full allocations at planned prices with zero fees
  and slippage. Paper executions and results never enter real financial readers.
- **Smoother journal work.** Duplicate a plan into a new Draft, save from the
  expanded journal, and record manual executions with field-level validation.
  Settings selects Local or UTC time throughout; Activity and Review day
  boundaries remain explicitly UTC.

## Upgrading from 0.3.2

1. Stop web, every API and every worker/replica on all hosts, including
   `worker-notifications` and any optional `worker-paper`. Back up both database
   schemas, evidence, credential keys and private configuration together.
2. Preserve the owner GUID, Compose project and all storage, credential,
   authentication and TLS overlays. Set `VESSEL_VERSION=0.3.3` and pull the
   matching API/web images. Workers use the same API image.
3. Run the explicit `migrate` service before starting upgraded hosts. It applies
   these journal migrations in order; there is no new identity migration:

   | Journal migration | Purpose |
   | --- | --- |
   | `20261019132931_MonitorCoverage` | Per-Play stop coverage, populated by subsequent checks. |
   | `20261020085301_PlanPreflight` | Planning checklist snapshots. |
   | `20261020093407_ReviewCompletion` | Explicit review completion and append-only log. |
   | `20261020102320_UnresolvedStatus` | Unresolved declarations and execution evidence. |
   | `20261020112132_ManualCorrectionBatch` | Grouped correction history. |
   | `20261020155750_PaperTradingFoundation` | Isolated paper capital, accounts and simulated executions. |

4. Start matching API, web and worker images, then verify readiness and journal
   access. Existing records remain Real; previously Reviewed Plays stay reviewed.
   Paper stays off until enabled in Settings. Its optional scheduler needs
   `compose.paper.yaml --profile paper` and an explicit matching
   `VESSEL_AUTH_MODE`; keep existing module sets and overlays.

Historical ladder levels can change with exit-time ordering and consecutive
recovery wins. The scored result basis, pooled ladder, thresholds, 20-decided
window and exact-zero scratch rule remain unchanged.

This is not a rolling upgrade. Rollback uses the pre-upgrade backup with matching
previous images; down migrations refuse retained Unresolved history or paper
data. For earlier versions, follow the
[deployment upgrade requirements](https://github.com/sloppitty/vessel/blob/v0.3.3/deploy/README.md#upgrade),
including the v0.3.0 order-identity restriction. Application hosts never migrate
at startup.

and `web-latest`. Publication does not upgrade or migrate any installation.

## Known limits

- Paper v1 has no gap/ambiguity resolution or manual simulated-close endpoint.
  Affected reservations may stay held indefinitely and results remain unscored.
  Open/unresolved virtual equity is unknown. There are no paper notifications
  or continuous streams, and simulation never confirms an actual venue fill.
- Plan pre-flight never blocks planning. Process counts describe cases without
  rankings; a share is hidden below its own sample of ten. Post-hoc plans stay
  scored and carry the plan-written-after-first-execution badge.
- R remains an estimate from the initial planned-stop model. Execution-result
  bases are unchanged; funding stays separate without a proven combined basis.
- Imports remain bounded. Wallet mode remains opt-in with registration `Closed`
  pending the owner's real-wallet acceptance; publication does not activate it.
